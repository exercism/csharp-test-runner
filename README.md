# Exercism C# test runner

A test runner automatically verifies if a submission passes all the tests.

This repository contains the C# test runner, which implements the [test runner interface][test-runner-interface].

## Running the tests

To run a solution's tests, follow these steps:

1. Open a command prompt in the root directory.
1. Run `./run.ps1 <exercise> <input-directory> <output-directory>`. This script will:
   1. Make sure all tests run (no skipped tests) for the solution found in `<input-directory>`.
   1. Run all the tests.
   1. Once the script has completed, the test results will be written to `<output-directory>/results.json`.

## Running the tests using Docker

To run a solution's tests using a Docker container, follow these steps:

1. Open a command prompt in the root directory.
1. Run `./run-in-docker.ps1 <exercise> <input-directory> <output-directory>`. This script will:
   1. Make sure all tests run (no skipped tests) for the solution found in `<input-directory>`.
   1. Run all the tests.
   1. Once the script has completed, the test results will be written to `<output-directory>/results.json`.

## How the tests are run

The runner builds the project and then runs the xUnit v3 test executable directly, which writes xUnit's XML report. It has two ways to build the project:

1. **The fast path** compiles the solution with Roslyn inside the runner's own process. It skips `dotnet restore` and MSBuild, which take most of the time in a normal run.
1. **MSBuild** restores and builds the project with `dotnet build`.

The runner uses MSBuild whenever the fast path can't handle the solution. To turn the fast path off, for example to compare its results with MSBuild's, set the environment variable `EXERCISM_FAST_PATH=off`.

### Project shapes

The fast path still compiles each solution with the settings from its own `.csproj`. Exercises with identical project files (apart from their names) compile the same way, so the runner groups them into shapes. The `shapes/` folder holds one template project file for each shape found in the track's history since the switch to xUnit v3.

When the Docker image is built, `bin/build-shapes.sh` builds each template with the real .NET SDK. Every template also uses the files in `shapes/` itself: two placeholder source files, and a `Directory.Build.targets` file that saves the compiler command line. It keeps the exact compiler command line, the source files generated by the SDK and packages, and a folder with every dependency precompiled with ReadyToRun. At run time, the runner reduces the solution's `.csproj` to a key (see `ProjectShape.cs`) and looks for a template with the same key. If it finds one, it compiles the solution's files with that template's compiler arguments.

### When the fast path hands over to MSBuild

The runner prints `Fast path not used: <reason>` and uses MSBuild if any of these is true:

- No shape matches the project file. This happens if the project file has anything other than plain properties, `Using` items and `PackageReference` items, or if it has a combination of settings with no template.
- The solution folder has a `bin` or `obj` folder, another project file, a `Directory.Build.*` or `Directory.Packages.props` file, `global.json`, `nuget.config`, `AssemblyInfo.cs`, a `.resx` or `.globalconfig` file, or an `.editorconfig` that changes diagnostics.
- A source file is not valid UTF-8, or uses something that needs a source generator or analyzer (such as `[GeneratedRegex]`), or has a `[Fact]` or `[Theory]` outside the test file.

### Adding a new shape

If the track changes an exercise's `.csproj` (for example to bump a package version or add a package), solutions for that exercise will use MSBuild until the image has a matching shape. They will still pass or fail correctly, just more slowly. To add the new shape:

1. Make sure any new package is pre-installed in the `Dockerfile`, as before.
1. Regenerate the shapes from a checkout of the track repo, with `bin/generate-shapes.cs shapes <path to exercism/csharp>`. You can also copy the new `.csproj` into a new folder as `shapes/<n>/ExercismShape.csproj` by hand.
1. Rebuild the image. The build log says `Built shape ...` for each shape, or `Skipping shape ...` if a template failed to build.
1. Run an exercise with the new project file, and check that the runner does not print `Fast path not used: unknown project shape`.

### Scripts

The scripts in this repository are written in PowerShell. As PowerShell is cross-platform nowadays, you can also install it on [Linux](https://docs.microsoft.com/en-us/powershell/scripting/install/installing-powershell-core-on-linux?view=powershell-6) and [macOS](https://docs.microsoft.com/en-us/powershell/scripting/install/installing-powershell-core-on-macos?view=powershell-6).
